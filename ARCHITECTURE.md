# Mission Analyzer — структура проекта

Справка по модулям, зависимостям и папкам в рантайме.

## Бібліотеки Python, які потрібно встановити

Стандартної бібліотеки вистачає для базового запуску (GUI, парсинг,
аналіз, графіки, карта миссии, кеш тайлів). Але для повноцінної роботи
всіх функцій, доданих останнім часом (метео, PDF, підключення до
ArduPilot), потрібні наступні pip-пакети:

| Пакет | Навіщо | Обов'язковий? |
|---|---|---|
| **reportlab** | Кнопка «Зберегти PDF» на сторінці «Аналіз» — без нього кнопка покаже повідомлення з інструкцією встановити пакет, решта програми працює | Так, лише для експорту в PDF |
| **pyserial** (`serial`) | Список COM-портів і підключення до ArduPilot у панелі під UA/EN на сторінці «Місія» | Ні — без нього поле порту просто редагується вручну |
| **pymavlink** | Повноцінне MAVLink-з'єднання (Read/Write місії на борт, heartbeat) під час підключення до ArduPilot | Ні — без нього код відкриває голий serial-порт без MAVLink-рукостискання |
| **Pillow** (`PIL`) | Якісне масштабування логотипу (LANCZOS) і декодування JPEG-тайлів (Google Satellite/Гібрид) | Ні — без нього лого масштабується грубіше, JPEG-тайли показують заглушку |

Встановити все одразу:
```
pip install reportlab pyserial pymavlink Pillow
```

Все інші імпорти — стандартна бібліотека Python (3.10+): `tkinter`,
`urllib.request`, `json`, `threading`, `math`, `io`, `os`, `sys`, `re`,
`datetime`, `calendar`, `tempfile`, `webbrowser`, `subprocess`, `glob`,
`types`.

Метеодані (Open-Meteo, `api.open-meteo.com`) отримуються напряму через
`urllib.request` — окремого пакета для цього не треба.

## Архітектура (коротко)

```
main.py  →  сплэш-экран (лого + версия)  →  app.py (GUI, Tkinter)
                                                │
              ┌─────────────┬──────────────────┼──────────────────┬─────────────┐
              │             │                  │                  │             │
          ядро          відрисовка        інфраструктура      мережа       MAVLink/
       (без GUI)         (Canvas)             GUI            (карти/погода) ArduPilot
              │             │                  │                  │             │
   waypoints.py    elevation_view.py    i18n.py, theme.py   online_tiles.py   pymavlink
   geo.py          angle_view.py        icons.py            occupied_layer.py pyserial
   srtm.py         landing_view.py      settings.py         Open-Meteo API    (опційно)
   analyzer.py     map_view.py          version.py          (urllib, вбудовано)
                                         changelog.py
```

Правило те саме: модулі даних (`waypoints`, `geo`, `srtm`, `analyzer`)
нічого не знають про Tkinter. Модулі відрисовки (`elevation_view`,
`angle_view`, `landing_view`, `map_view`) знають про Canvas, але не про
кнопки/сторінки/файли. `app.py` — єдине місце, яке знає про все
одразу (це оболонка, а не логіка).

## Модулі

### Ядро (логіка, без GUI)

| Файл | Що робить | Залежить від |
|---|---|---|
| `waypoints.py` | Модель точки маршруту (`Waypoint`), розбір `.waypoints` (QGC WPL 110), довідник імен MAVLink-команд (`command_name`) | стандартна бібліотека |
| `geo.py` | Дистанції (haversine), азимут (bearing), кути повороту, перерахунок lat/lon ↔ тайли/пікселі сліппі-карти | `waypoints.py` |
| `srtm.py` | Читання рельєфу з тайлів SRTM — за іменем файлу (`N50E030`), розширення будь-яке | стандартна бібліотека |
| `analyzer.py` | `MissionAnalyzer` — усі перевірки, профілі для графіків, глісада заходу на посадку, звіт, експорт CSV. Атрибути `nav_wps`/`all_wps`/`issues` та методи `elevation_profile()`, `landing_approach_*()` — основне API, яким користується `app.py` | `waypoints.py`, `geo.py`, `srtm.py`, `i18n.py` |

### Відрисовка (Canvas, не GUI-логіка)

| Файл | Що робить | Залежить від |
|---|---|---|
| `elevation_view.py` | `draw_elevation_profile()` — графік висоти всієї місії; `draw_takeoff_profile()` (новий) — той самий графік, обрізаний по перших N точках маршруту (крок 10м замість 50) для профілю зльоту | `analyzer.py`, `i18n.py` |
| `angle_view.py` | Графік кута нахилу траєкторії з порогом ±N° | `analyzer.py`, `i18n.py` |
| `landing_view.py` | Глісада заходу на посадку: профіль + рельєф, підписи дистанції/азимуту/кута, мітки `DO_CHANGE_SPEED`. Відступи згори/знизу тепер адаптивні до висоти канваса (не сплющується на малих панелях) | `analyzer.py`, `i18n.py` |
| `map_view.py` | `compute_tile_bounds`/`fetch_tiles`/`render_tiles` — карта всього маршруту (як на «Місія»). Нове: `compute_area_tile_bounds()`/`render_area_map()` — квадратна карта 4×4 км навколо довільної точки (старт/посадка) зі стрілками азимуту польоту й вітру | `analyzer.py`, `geo.py`, `i18n.py` |

### Джерела даних з інтернету

| Файл / джерело | Що робить | Залежить від |
|---|---|---|
| `online_tiles.py` | Тайли карти: OSM / Google Maps / Satellite / Hybrid (`PROVIDERS`), диск-кеш, повтори при збоях | стандартна бібліотека (`urllib`) |
| `occupied_layer.py` | GeoJSON окупованих територій (deepstatemap.live), диск-кеш по даті. URL тепер редагується в «Конфігурація → Картографічні та метеосервіси» | стандартна бібліотека |
| Open-Meteo (`api.open-meteo.com`) | Прогноз погоди (вітер, температура, схід/захід сонця) для точок старту/посадки — безкоштовно, без ключа, до 16 днів наперед. Викликається напряму з `app.py` (`_meteo_worker`) через `urllib.request`, окремого модуля немає | стандартна бібліотека |

### Інфраструктура GUI

| Файл | Що робить |
|---|---|
| `i18n.py` | Локалізація UA/EN. Частина нових написів (діалог погоди, MAVLink-повідомлення) захардкоджені українською прямо в `app.py`, бо `i18n.py` не мав відповідних ключів на момент їх додавання |
| `theme.py` | Тема оформлення. Акцентний колір — **зелений** (`GREEN_ACCENT #5A961E`/`GREEN_ACCENT_HOVER #6FB026`/`GREEN_DARK #355E12`, взяті піпеткою з логотипу), замість колишнього синього. Шапка й навбар — **чорні** (`HEADER_BG #000000`). `NAVY_DARK`/`NAVY` лишились для статус-бару й неактивної вкладки в «Аналіз»/«Довідка». `apply_theme(root)` повертає палітру, `set_window_icon()` — іконка вікна |
| `icons.py` | Іконка «Місія» тепер — **маршрут польоту** (ламана лінія з точками повороту й стрілкою напрямку), а не пін-мітка |
| `settings.py` | Збереження/завантаження `settings.json`: шляхи SRTM/кешу, пороги, зум, мова, провайдер, а також нові поля — дата/час польоту, крейсерська швидкість, URL картографічних/метеосервісів |
| `version.py` | Рядок версії |
| `changelog.py` | Історія версій |

### Оболонка

| Файл | Що робить |
|---|---|
| `app.py` | Все вікно: 4 сторінки з навігацією (іконка+підпис). Див. розділ «Сторінки» нижче — значну частину логіки додано/перероблено |
| `main.py` | Точка входу: сплэш-екран → `app.main()` |

## Сторінки застосунку (app.py)

### Місія
Кнопки «Завантажити»/«Зберегти» (файл, як і раніше) — реалізовані як
пара `tk.Button` (не `ttk.Button`): клік робить кнопку чорною й трохи
меншою, тримає стан до кліку по другій кнопці (та сама логіка, що й у
кнопок навігації). «Зберегти» відкриває один системний діалог з
вибором типу файлу (CSV / Waypoints) у випадаючому списку.

Під перемикачем UA/EN — панель підключення до ArduPilot (лише на цій
сторінці): випадаючі списки порту й швидкості обміну (без підписів,
як у Mission Planner) + кнопка «Підєднатись»/«Роз'єднати». При
підключенні поруч із «Завантажити»/«Зберегти» з'являються ще дві
кнопки — **Read**/**Write**, які читають/пишуть місію на борт напряму
через MAVLink (`MISSION_REQUEST_LIST`/`MISSION_COUNT`+`MISSION_ITEM_INT`),
минаючи файлову систему.

Зум карти прибрано зі сторінки «Місія» — керування лише колесом миші;
початковий/дефолтний зум переїхав у «Конфігурацію». При відрисовці
карти зум автоматично підбирається під ліміт тайлів (без спливаючого
попередження — просто мовчки знаходить придатний зум).

Таблиця місії: колонка «Фрейм» показує текстову назву (`Absolute`,
`Global Rel. Alt`, `Global Terrain Alt`...) замість числа
(`_frame_name()` у `app.py`). Нульова Home-точка (`index == 0`) у
таблиці не показується — як і в Mission Planner.

### Аналіз
Замінено на **3 вкладки** (було 5: Звіт/Графік висоти/Кут
траєкторії/Глісада/Метео), кожна — **один спільний вертикальний
скрол** (`Canvas`+`Scrollbar`, без `PanedWindow` і без вкладених смуг
прокрутки — текстові блоки й карта своїх скролів не мають). Структура
уніфікована на всіх трьох: **текст → карта (квадратна, 4×4 км або весь
маршрут) → профіль висоти**.

- **Зліт** — текст (погода Open-Meteo для точки старту) → карта
  «Старт — 4×4 км» → профіль висоти зльоту (`draw_takeoff_profile`,
  перші ~3 точки маршруту).
- **Траєкторія** — текст (звіт по висоті + звіт по куту, розібраний з
  `analyzer.print_report()` за заголовками `=== ... ===`) → карта
  всього маршруту («вигляд згори», та сама логіка, що на «Місія») →
  графік висоти → графік кута.
- **Глісада** — текст (проблеми глісади зі звіту + погода посадки) →
  карта «Посадка — 4×4 км» → графік глісади.

Над вкладками — рядок: дата польоту (кнопка, відкриває власний
модальний календар без зовнішніх бібліотек), час вильоту (випадаючий
список годин 00–23), розрахований час прибуття (автоматично: сума
відстаней між точками маршруту / крейсерська швидкість з
«Конфігурації»), кнопка «Отримати метео» (фоновий потік →
`api.open-meteo.com`).

Під перемикачем UA/EN на цій сторінці — кнопка «Зберегти PDF»
(`reportlab`): текстовий звіт (без растеризації графіків/карт) із
чотирьох блоків вище.

Карти 4×4 км і карта маршруту — квадратні (висота автоматично
дорівнює ширині при зміні розміру вікна), панорамування —
перетягуванням миші, без власних смуг прокрутки.

### Конфігурація
Пороги висоти/кута, крейсерська швидкість (м/с, для розрахунку часу
прибуття), шлях SRTM, шлях диск-кешу карти, тип підложки, зум за
замовчуванням (переїхав сюди зі сторінки «Місія»), слой окупованих
територій. Новий блок **«Картографічні та метеосервіси»** — URL шару
окупованих територій, Windy, Open-Meteo, Global Wind Atlas (кожен —
поле + кнопка «↗» відкрити в браузері).

### Довідка
Без змін: Довідка + Історія змін.

Мова інтерфейсу (UA/EN) перебудовує весь UI (`_build_ui()` заново).

## Мережа

- `*.tile.openstreetmap.org` / `mt0-3.google.com` — тайли карти (як і
  раніше, для карти на «Місія», для карт 4×4 км і карти маршруту в
  «Аналіз»)
- `raw.githubusercontent.com` — шар окупованих територій
- `api.open-meteo.com` — прогноз погоди (безкоштовно, без ключа)
- COM-порт / MAVLink — локальне з'єднання з польотним контролером, не
  інтернет

## На що звернути увагу при збірці в exe (PyInstaller)

- Додай `reportlab` у `pip install` і в спек PyInstaller, якщо потрібен
  експорт у PDF — інакше кнопка на сторінці «Аналіз» видасть коректне
  повідомлення про відсутність пакета, але не працюватиме.
- `pyserial`/`pymavlink` — опційні; без них панель підключення на
  «Місія» відображається, але список портів порожній і підключення
  впаде з зрозумілою помилкою замість MAVLink-рукостискання.
- Решта пунктів (лого через `--add-data`, права на запис
  `settings.json`/`map_cache`/`srtm`) — без змін відносно попередньої
  версії документа.
