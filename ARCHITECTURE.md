# Mission Analyzer — структура проекта

Справка по модулям, зависимостям и папкам в рантайме. Актуально на
версию `1.0.0` (см. `version.py` / вкладку «Довідка → Історія змін»).

## Архитектура (коротко)

```
main.py  →  сплэш-экран (лого + версия)  →  app.py (GUI, Tkinter)
                                                │
                    ┌───────────────────────────┼───────────────────────────┐
                    │                            │                           │
              ядро (без GUI)              отрисовка (Canvas)          инфраструктура
                    │                            │                           │
   waypoints.py ─┐  │        elevation_view.py ─┐│         i18n.py     theme.py
   geo.py         ├─┤        angle_view.py      ││         icons.py    settings.py
   srtm.py        │ │        landing_view.py    ├┤         version.py  changelog.py
   analyzer.py ───┘ │        map_view.py       ─┘│
                    │                            │
              online_tiles.py, occupied_layer.py (сеть)
```

Правило то же, что и раньше: модули данных (`waypoints`, `geo`, `srtm`,
`analyzer`) ничего не знают про Tkinter. Модули отрисовки (`elevation_view`,
`angle_view`, `landing_view`, `map_view`) знают про Canvas, но не про
кнопки/страницы/файлы. `app.py` — единственное место, которое знает про
всё сразу (это оболочка, а не логика).

## Модули

### Ядро (логика, без GUI)

| Файл | Что делает | Зависит от |
|---|---|---|
| `waypoints.py` | Модель точки маршрута (`Waypoint`), разбор `.waypoints` (QGC WPL 110), справочник имён MAVLink-команд (`command_name`) | стандартная библиотека |
| `geo.py` | Дистанции (haversine), азимут (bearing), углы поворота, пересчёт lat/lon ↔ тайлы/пиксели слиппи-карты | `waypoints.py` |
| `srtm.py` | Чтение рельефа из тайлов SRTM — по имени файла (`N50E030`), расширение любое (`.hgt`, `.doc` и т.п.) | стандартная библиотека |
| `analyzer.py` | `MissionAnalyzer` — все проверки (низкая высота по файлу/по AGL в точках и вдоль линии полёта, острые повороты, угол набора/снижения), профили для графиков, глиссада захода на посадку (+ команды `DO_CHANGE_SPEED`), отчёт, экспорт CSV | `waypoints.py`, `geo.py`, `srtm.py`, `i18n.py` |

### Отрисовка (Canvas, но не GUI-логика)

| Файл | Что делает | Зависит от |
|---|---|---|
| `elevation_view.py` | График высоты (рельеф + высота миссии), сквозная нумерация реальных точек | `analyzer.py`, `i18n.py` |
| `angle_view.py` | График угла наклона траектории с порогом ±N°, ось X — только номера точек | `analyzer.py`, `i18n.py` |
| `landing_view.py` | Глиссада захода на посадку: профиль + рельеф на последних отрезках до LAND, подписи дистанции/азимута/угла лесенкой, метки `DO_CHANGE_SPEED`, названия MAVLink-команд у каждой точки | `analyzer.py`, `i18n.py` |
| `map_view.py` | Расчёт диапазона тайлов (`compute_tile_bounds`), параллельная загрузка (`fetch_tiles`, в фоновом потоке), отрисовка тайлов + слоя оккупированных территорий + маршрута (`render_tiles`), панорамирование | `analyzer.py`, `geo.py`, `i18n.py` |

### Источники данных из интернета

| Файл | Что делает | Зависит от |
|---|---|---|
| `online_tiles.py` | Тайлы карты: OpenStreetMap / Google Maps / Google Satellite / Google Гибрид (`PROVIDERS`), диск-кеш по папкам под каждый провайдер, повторные попытки при сетевых сбоях | стандартная библиотека (`urllib`) |
| `occupied_layer.py` | GeoJSON оккупированных территорий (зеркало deepstatemap.live на GitHub), откат на предыдущую дату, диск-кеш по дате | стандартная библиотека (`urllib`, `json`) |

### Инфраструктура GUI

| Файл | Что делает |
|---|---|
| `i18n.py` | Локализация UA/EN (без русского — это только язык переписки с разработчиком). Все подписи, заголовки ошибок, тексты отчёта и графиков идут отсюда. Переключение — `i18n.set_lang()`/`get_lang()`, подстановка — `i18n.t(key, **kwargs)` |
| `theme.py` | Тема оформления «а-ля Mission Planner»: тёмно-синяя шапка/статус-бар, синие акцентные кнопки, подсвеченные вкладки. `apply_theme(root)` возвращает палитру цветов, `set_window_icon(root, path)` — иконка окна |
| `icons.py` | Векторные иконки навигационных кнопок (пин, гистограмма, шестерёнка, знак вопроса) — рисуются на Canvas кодом, не картинками, поэтому не мылятся при любом масштабе |
| `settings.py` | Сохранение/загрузка настроек (`settings.json` рядом с программой) — путь к SRTM/кэшу карт, пороги, зум, язык, выбранный провайдер и т.п. |
| `version.py` | Строка текущей версии (`VERSION`) — показывается на сплэше и в «Довідка → Історія змін» |
| `changelog.py` | История версий (`ENTRIES`), билингвально; `format_changelog(lang)` отдаёт готовый текст для вкладки «Історія змін» |

### Оболочка

| Файл | Что делает |
|---|---|
| `app.py` | Всё окно: 4 страницы (Місія / Аналіз / Конфігурація / Довідка) с навигацией иконка+подпись, обработчики кнопок, фоновые потоки для сети, связывает все модули выше |
| `main.py` | Точка входа: сначала сплэш-экран (чёрный фон, лого, версия), потом `app.main()` |

### Не используются в текущем потоке (можно не тащить в exe)

| Файл | Статус |
|---|---|
| `tilecache.py` | Устаревший офлайн-кэш Mission Planner (`gmapcache`/`Data.gmdb`). Заменён на `online_tiles.py`. Нигде не импортируется. |
| `check_coverage.py` | Отдельная диагностическая утилита (проверка покрытия офлайн-кэша по зумам, осталась со времён `tilecache.py`) |
| `test_internet.py` | Отдельная диагностическая утилита (проверка сетевых/прокси проблем) |

## Страницы приложения (app.py)

| Страница | Что на ней |
|---|---|
| **Місія** | Кнопки «Завантажити» (диалог выбора файла → парсинг → полный анализ → карта, всё за один клик) и «Зберегти» (CSV). До загрузки — чёрный плейсхолдер с лого вместо пустых таблицы/карты. После загрузки — таблица всех команд файла (как в Mission Planner: #, Команда, P1-P4, Шир., Довг., Вис., Фрейм, Відст., AZ) и карта маршрута с зумом (колесо мыши) |
| **Аналіз** | 4 вкладки: Звіт, Графік висоти, Кут траєкторії, Глісада |
| **Конфігурація** | Пороги высоты/угла, папка SRTM, папка диск-кэша карты, тип подложки карты, слой оккупированных территорий |
| **Довідка** | 2 вкладки: Довідка (описание функций) и Історія змін (из `changelog.py`) |

Язык интерфейса (UA/EN) переключается кнопками в шапке — весь UI
перестраивается (`_build_ui()` заново), состояние (файл, пороги,
текущая страница, загруженная миссия) сохраняется.

## Зависимости (внешние пакеты)

**Обязательных внешних пакетов нет** — всё на стандартной библиотеке
Python: `tkinter`, `urllib`, `json`, `dataclasses`, `pathlib`, `array`,
`math`, `csv`, `threading`, `concurrent.futures`, `sqlite3` (не
используется в текущем потоке, остался в `tilecache.py`).

**Опционально:**
- **Pillow** (`pip install Pillow`) — качественное уменьшение логотипа
  (шапка/сплэш/плейсхолдер) через LANCZOS и декодирование JPEG-тайлов
  (Google Satellite/Гибрид). Без него логотип масштабируется грубее
  (subsample), а JPEG-тайлы показывают заглушку «JPEG без Pillow» —
  остальное работает без изменений.

**Нужен Python 3.10+** (синтаксис `X | None` в аннотациях; во всех
модулях есть `from __future__ import annotations`, так что формально
может завестись и на более старых версиях, но не проверялось).

## Файлы-ассеты (не .py)

| Файл | Что это |
|---|---|
| `icon.png` (или `logo.png`) | Логотип — иконка окна, картинка в шапке, сплэш-экран, плейсхолдер на странице «Місія». Ищется автоматически рядом с .py файлами, при отсутствии просто не показывается (ничего не ломается) |
| `settings.json` | Создаётся программой автоматически при первом сохранении настроек. Удали файл, чтобы сбросить всё на дефолты |

## Папки, нужные в рантайме

Создаются программой автоматически при первом использовании:

| Папка (по умолчанию) | Что внутри | Создаётся |
|---|---|---|
| `srtm` (относительно .exe, поле «Рельєф (SRTM)» на странице «Конфігурація») | Тайлы рельефа — имя файла вида `N50E030`, расширение любое | Пользователь копирует сам, программа только читает |
| `map_cache` (относительно .exe, поле «Диск-кеш карти») | Подпапки по провайдерам: `map_cache/osm/`, `map_cache/google_roadmap/`, `map_cache/google_satellite/`, `map_cache/google_hybrid/` — файлы тайлов `{z}_{x}_{y}.tile` | Программой автоматически |
| `map_cache/deepstate/` | Кэш GeoJSON слоя оккупированных территорий, по одному файлу на дату | Программой автоматически |

Пути к `srtm` и `map_cache` — текстовые поля (`StringVar`), по
умолчанию относительные (без буквы диска) — работают откуда угодно,
если не указать другой путь через «Огляд...».

## Сеть

Для полной работы нужен исходящий доступ в интернет к:
- `*.tile.openstreetmap.org` (или `mt0-3.google.com`, если выбран провайдер Google) — тайлы карты
- `raw.githubusercontent.com` — слой оккупированных территорий

Без сети работает всё, кроме карты на странице «Місія» (сама миссия,
таблица, отчёт, все графики — не требуют интернета вообще, если уже
есть локальные SRTM-тайлы).

## На что обратить внимание при сборке в exe (PyInstaller)

- `tkinter` обычно подхватывается PyInstaller автоматически, но стоит
  явно проверить, что собранный exe открывает окно (иногда нужен
  `--hidden-import tkinter` или включение `tcl`/`tk` DLL вручную на
  Windows, если использовался нестандартный Python).
- Явных файлов данных (кроме `icon.png`/`logo.png`) в проекте нет — но
  лого нужно явно включить через `--add-data`, иначе шапка/сплэш/
  плейсхолдер останутся без картинки (не критично, просто без лого).
- Если решишь включить Pillow в сборку ради JPEG-тайлов и качественного
  масштабирования лого — не забудь его и в `pip install` при подготовке
  окружения для сборки, и как зависимость в спеке PyInstaller.
- Проверь, что exe умеет создавать папки `map_cache`/`srtm` рядом с
  собой, если антивирус/UAC не режет запись в `Program Files` —
  возможно, стоит по умолчанию класть кэш в `%LOCALAPPDATA%` вместо
  папки рядом с exe, если приложение будет ставиться в защищённую
  системную папку (сейчас пути относительные, читаются от текущей
  рабочей директории — это стоит перепроверить после сборки, у exe
  рабочая директория иногда отличается от папки, где он лежит).
- `settings.json` пишется рядом с .py/.exe файлом — та же проблема с
  правами записи в защищённые системные папки, что и для `srtm`/`map_cache`.
